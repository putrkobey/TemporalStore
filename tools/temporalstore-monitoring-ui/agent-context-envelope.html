Public Agent Contract

Simple Zep/Mem0-style input for agents and hook integrations; TemporalStore schemas stay internal.

Minimal Ingest

{
  "messages": [
    {"role": "user", "content": "Alice approved the GPU request."}
  ]
}

Required

  • matrixark_ingest: messages[].role, messages[].content
  • matrixark_retrieve: query
  • matrixark_feedback: messages[].role, messages[].content
  • matrixark_replay: context_pack_id

Recommended Envelope

{
  "messages": [
    {
      "role": "user",
      "content": "Alice approved the GPU request.",
      "name": "Alice",
      "created_at_ms": 1781500000000
    }
  ],
  "scope": {
    "user_id": "alice",
    "session_id": "agent-session-scale-1",
    "team": "infra_team",
    "project": "project_1"
  },
  "metadata": {
    "source": "cursor",
    "node_path": ["company_a", "infra_team", "project_1", "approvals"]
  }
}

Optional Quality Hints

  • scope.user_id: optional user memory scope
  • scope.session_id: optional thread/run scope
  • Send either one as the minimum useful scope; send both when available
  • scope.team/project: routing and filtering hints
  • metadata.source: source label
  • metadata.node_path: optional tree/path hint
  • metadata.agent_extraction: optional host-provided extraction hints
  • agent_hook: only for auto-captured host hooks

Extraction Policy

MatrixArk always extracts and canonicalizes; callers do not toggle the internal pipeline.

Caller Contract

Agents send messages, scope, metadata, and hook evidence. They can include optional extraction hints, but MatrixArk still validates and normalizes them.

Internal Work

MatrixArk chooses deterministic extraction, OSS models, OpenAI/provider models, or agent hints, then writes its own TemporalStore ContextEvent, Entity, Index, Summary, Embedding, and Audit records.

Retrieve And Feedback

Keep calls small; add context-pack refs only when the agent has them.

Retrieve

{
  "query": "what GPU approvals are current?"
}
  • scope: optional filter/scope hint
  • max_context_tokens: optional, defaults to 10000

Feedback

{
  "messages": [
    {"role": "user", "content": "Yes, that answer is correct."}
  ]
}
  • context_pack_id: optional but best for reliable inference
  • accepted_refs, rejected_refs: optional evidence

Scope Policy

User id or session id is enough to start; both together give the best memory and thread grouping.

Preferred

Agents send both user_id and session_id. MatrixArk can combine long-term user memory with precise same-thread grouping for query understanding, confirmation detection, feedback memory, and context extraction.

Fallback

If only session_id is present, MatrixArk uses thread/run memory. If only user_id is present, MatrixArk uses user-level memory and warns when it is used for confirmation/correction inference.

Internal Model Boundary

Agents send Mem0-style messages and scope. MatrixArk owns extraction and serving schemas.

Agent Sends

  • messages: chat, tool, resource, or feedback text
  • scope: user_id, session_id, team/project hints
  • metadata: source, node hints, reply/context-pack references
  • agent_hook: optional lifecycle evidence from host integrations

MatrixArk Writes

  • ContextEvent, ContextEntity, ContextIndex
  • ContextSummary and summary embeddings
  • ContextCompressionEvent for cold windows
  • ContextPackAudit for replay and token-budget evidence
