Give your app long-term memory in one API call.

Two HTTP endpoints — /v1/ingest to remember, /v1/retrieve to recall. Works from any language. No API key required to start. You control exactly whose memory it is.

Quickstart #

Point at your gateway (base_url = its origin, default port 8080). In the current default (dev) mode you don't need an API key — just send JSON.

1 · Remember something

curl -X POST http://saparo.ai:8080/v1/ingest \
 -H "Content-Type: application/json" \
 -d '{
   "kind": "message",
   "messages": [
     {"role":"user","content":"I prefer dark roast coffee"}
   ],
   "scope": {"tenant_id":"saparo","user_id":"alice","session_id":"s-42"}
 }'

2 · Recall it

curl -X POST http://saparo.ai:8080/v1/retrieve \
 -H "Content-Type: application/json" \
 -d '{
   "query": "what coffee does alice like?",
   "scope": {"tenant_id":"saparo","user_id":"alice","session_id":"s-42"}
 }'
# → context pack containing "dark roast coffee"

That's the whole loop. Everything below is detail on how memory is routed, how to ingest large files/skills, and how to lock it down for production.

The one concept: scope = identity & routing #

Memory is partitioned by a structured scope object — not parsed from the message text. The message content is what gets extracted (facts, entities, summaries, embeddings); who it belongs to is always explicit:

"scope": {
  "account_id": "acct_saparo",   // billing/org
  "tenant_id":  "saparo",        // your customer / workspace
  "user_id":    "alice",         // the end-user
  "session_id": "s-42"           // the conversation/session
}
FieldMeaningWhere it comes from
account_id / tenant_idBilling org / workspace — the hard isolation boundaryEnforced mode: pinned from the API key (un-spoofable). Dev mode: you assert it in scope.
user_id / session_idThe end-user & conversation — the per-user memory axisAlways from your request scope (your app vouches for it). Optional — omit for tenant-level memory.

Same scope in → same memory out. To store memory for a given user/session, pass that scope on ingest; to read it back, pass the same scope on retrieve.

Message & scope schema #

An ingest call = one scope (one user + session) + N messages (each with its own role). Identity is per-call; role is per-message.

{
  "kind": "message",              // message | resource | skill | feedback | business_data

  "scope": {                      // ── PER-CALL identity (applies to the whole batch) ──
    "account_id": "acct_saparo",  //   optional · pinned from the API key in enforced mode
    "tenant_id":  "saparo",       //   optional · pinned from the API key in enforced mode
    "user_id":    "alice",        //   optional · the end-user
    "session_id": "s-42"          //   optional · the conversation/session this batch belongs to
  },

  "messages": [                   // ── PER-MESSAGE role + content ──
    {"role": "user",      "content": "I prefer dark roast"},   // role ∈ {user,assistant,tool,system}
    {"role": "assistant", "content": "Noted."}                  // content = non-empty string
  ],

  "sharing_scope": "private_user",       // optional · private_user | tenant_shared | global_shared
  "ingestion_time_ms": 1699999999999      // optional · defaults to now
}

Validation (server-enforced — bad input → 400, never silent)

messages[]Non-empty list; each entry an object.
