MatrixArk Context Secondary Index Mechanism

Context secondary indexes follow the same TemporalStore principle as non-context feature data: primary data is timestamp-keyed, while compact secondary structures help prefilter candidates before scoring.

Two Context Index Paths

Legacy compatibility refs

ctxidx:{tenant_hash}:{index_name}:{index_value_hash}:{scope_hash}
  timestamp_key -> ContextIndexRef

Compact postings

ctxidx2:{tenant_hash}:{scope_hash}:{index_name}:{time_bucket_ms}
  timestamp_key -> posting payload with refs + index_value_hash

Why Counts Do Not Match Item Counts

Secondary-index counts are not expected to equal context item counts. One item can emit several index families, while one compact posting can contain many item refs.

ContextEvent 123
  -> source_type:message
  -> event_type:approval
  -> entity_type:approval_state
  -> keyword_id:gpu
  -> keyword_id:aurora

That is one event but multiple index memberships. The opposite also happens:

ctxidx2:tenant:scope:event_type:20260704093000000
  -> index_value_hash=approval
  -> ref_hashes=[123, 456, 789, ...]

That is many refs in one posting object.
