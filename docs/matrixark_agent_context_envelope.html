MatrixArk Agent Context Envelope

What Codex, Claude, Cursor, and other agents can send, and how MatrixArk resolves identity and access safely.

﻿# MatrixArk Agent Context Envelope

Date: 2026-06-25

Product Rule

Agents should send as much useful context as they already know, but they should not be trusted as the final authority for identity or access. MatrixArk accepts the agent-provided envelope as hints and evidence, then resolves and enforces the final `account_id`, `tenant_id`, `user_id`, `session_id`, API key scopes, roles, SSO mapping, audit, and per-user/session isolation on the server side.

This is the safe model for Codex, Claude, Cursor, and other AI agents:


agent sends what it knows
-> MatrixArk normalizes the envelope
-> API key / SSO / local mode resolve identity
-> access scope filters every write and retrieval
-> audit records what was accepted, inferred, rejected, and replayed

What Codex Can Send

Codex can integrate with MatrixArk through MCP calls or lifecycle hooks. The current Codex manual documents MCP configuration and hook events such as `UserPromptSubmit`, `PostToolUse`, `PreCompact`, `PostCompact`, `Stop`, `SessionStart`, and others. Practically, MatrixArk should expect Codex to provide some of these fields when available, not all of them every time.

Codex does not automatically expose a stable MatrixArk account/user schema. For local hooks, default identity comes from config/env (`MATRIXARK_ACCOUNT_ID`, `MATRIXARK_TENANT_ID`, `MATRIXARK_USER_ID`) or local defaults. For cloud/product mode, MatrixArk API keys and optional SSO mapping become authoritative.

Minimal Message Ingest

An agent can send only a message. MatrixArk will fill local defaults for missing scope in local/dev mode.


{
  "messages": [
    {"role": "user", "content": "Alice approved the GPU purchase after finance reviewed the budget."}
  ]
}

MatrixArk normalizes this into a scoped event. In local mode defaults are:


account_id = acct_local
tenant_id  = derived from agent name when known, otherwise tenant_local/user default
user_id    = local OS user or MATRIXARK_LOCAL_USER_ID
session_id = provided/captured when possible; otherwise optional or generated by hook state

Recommended Rich Envelope

When an agent knows more, send it. This is the recommended rich envelope for Codex/Claude/Cursor-style hooks:


{
  "messages": [
    {
      "role": "user",
      "content": "What is the current GPU approval and runbook blocker?",
      "created_at_ms": 1782415000000
    }
  ],
  "scope": {
    "account_id": "acct_hint_from_hook_or_config",
    "tenant_id": "tenant_codex",
